# 班级魔方签到类型自动识别与兼容提交设计

## 目标

课程签到中心根据远端页面的明确标记自动识别二维码、GPS、GPS + 拍照和密码签到，并立即切换到对应的参数界面。提交协议兼容 `AutoCheckBJMF-main` 的 GPS/扫码方式，并使用 `FuckBJMF-main` 补全密码签到识别与 `pwd` 参数。

## 参考协议

- `AutoCheckBJMF-main` 使用 `punch_gps(ID)` 发现 GPS 签到、使用 `punchcard_ID` 发现二维码签到，并统一向 `/student/punchs/course/{course_id}/{item_id}` 提交。
- GPS 兼容参数为 `id`、`lat`、`lng`、`acc`、`res` 和 `gps_addr`。
- GPS + 拍照不上传本地文件；提交时保留 `res` 参数。优先沿用远端表单已有值，没有值时发送空字符串。
- `FuckBJMF-main` 使用 `punch_pwd_frm_ID` 发现密码签到，并在通用参数基础上增加 `pwd`。

## 类型识别

识别采用“明确标记优先、表单字段补充、未知类型兜底”的顺序：

1. `punch_pwd_frm_{item_id}` 或可编辑的 `pwd`/密码字段识别为 `password`。
2. `punchcard_{item_id}` 识别为 `qr`。
3. `punch_gps({item_id})` 识别为 GPS 类型。
4. GPS 页面存在明确的拍照文字、文件控件、上传契约或 `gps_photo` 模式标记时识别为 `gps_photo`；单独出现通用隐藏字段 `res` 不能作为拍照依据。
5. 只有通用的 `lat`、`lng`、`acc` 隐藏字段时，不得覆盖列表页已经识别出的密码或二维码类型。
6. 没有足够证据时使用 `unknown`，界面显示“未知签到类型”，不默认推断为 GPS。

列表页得到的类型提示需要随签到项传入详情页解析。详情表单只有在提供更明确证据时才能覆盖该提示，避免通用 GPS 隐藏字段把密码签到误判为 GPS。

## 提交契约

- 有真实 POST 表单时优先使用表单的 action、method、隐藏字段和字段名称。
- 没有真实表单但存在可信类型标记时，合成 POST 契约，地址为 `/student/punchs/course/{course_id}/{item_id}`。
- 合成契约使用通用字段 `id`、`lat`、`lng`、`acc`、`res` 和 `gps_addr`。
- GPS 与 GPS + 拍照填写坐标和精度；`gps_addr` 默认为空。
- GPS + 拍照的 `res` 优先使用远端隐藏值，否则发送空字符串，不要求本地照片路径，也不调用照片上传接口。
- 二维码签到保留通用字段，未提供的坐标、照片资源和密码值发送空字符串。
- 密码签到保留通用字段，并将用户填写的签到密码写入远端字段 `pwd`；缺少密码时停止提交并提示用户。
- 真实表单使用其他已识别字段名时沿用真实字段名，不强制改写为上述默认名称。

## 界面与自动任务

- GPS：显示签到位置和定位精度。
- GPS + 拍照：显示签到位置和定位精度，并提示“兼容模式将自动附带 res”；不显示照片上传控件。
- 密码：显示签到密码输入框。
- 二维码：显示无需额外参数的提示。
- 未知类型：禁用执行按钮并提示重新同步，不展示不相关参数。
- 自动任务按签到项的实际 `mode` 选择参数。GPS + 拍照不再要求 `photo_path`，其执行参数与 GPS 相同并额外保留 `res`。

## 数据流

1. 同步签到项时解析列表页标记，生成带 `mode_hint` 的签到项。
2. 获取详情页后解析真实表单，并以证据优先级合并列表提示和表单结果。
3. 将最终 `mode`、表单 action、字段名和隐藏字段存入现有 `form_schema`。
4. 前端读取签到项 `mode`，自动切换表单。
5. 手动签到或自动任务根据存储的提交契约构造参数并发送一次请求。
6. 解析远端响应；结果无法确认时返回“请求已发送，结果未知”，不自动重复提交。

## 错误处理与安全边界

- 类型识别仅使用 GET 返回的页面结构，不发送试探性签到 POST。
- 密码、Cookie 和非空 `res` 不写入普通日志或诊断输出。
- 缺少必要坐标、密码或可信提交契约时返回等待参数状态，不发送请求。
- 显式表单 action 优先于兼容地址，降低远端路由变化带来的风险。
- 本次不增加数据库表或新照片上传接口，不恢复已删除的照片上传交互。

## 验证

仓库约定不保留测试专用文件，因此使用临时内存探针和生产构建验证：

- 使用 `punch_gps(ID)`、`punchcard_ID`、`punch_pwd_frm_ID` 和未知标记 HTML 验证类型识别。
- 验证密码页面即使同时包含 `lat`、`lng`、`acc`、`res` 隐藏字段，仍识别为 `password`。
- 验证合成 GPS、GPS + 拍照、二维码和密码契约均使用 `/student/punchs/course/...`。
- 验证各模式最终参数名称；GPS + 拍照必须包含 `res`，密码必须包含 `pwd`。
- 验证 GPS + 拍照不要求 `photo_path`，也不会进入上传接口。
- 运行后端语法编译、前端生产构建和 `git diff --check`。

## 非目标

- 不实现真实照片上传、图片资源加密或黑图资源生成。
- 不保证管理端能够查看 `res` 指向的图片。
- 不通过提交试探来判断签到类型。
- 不改变账号、课程、通知和运行记录等无关功能。
