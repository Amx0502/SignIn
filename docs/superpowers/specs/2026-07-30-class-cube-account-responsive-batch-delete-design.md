# 班级魔方账号自适应与批量删除设计

## 目标

- 账号卡片在不同页面宽度下完整保留状态和操作入口，不再截断右侧内容。
- 支持选择多个班级魔方账号并一次性删除。

## 前端布局

- 账号行改为明确列宽的网格布局：复选框、头像、可伸缩账号信息、状态、操作按钮。
- 账号信息列使用 `minmax(0, 1fr)`，名称过长时显示省略号；状态和操作按钮不收缩。
- 工作区左右栏根据可用宽度伸缩；达到现有响应式断点后继续改为上下排列。
- 账号列表不得通过横向滚动隐藏操作入口。

## 批量删除交互

- 每个账号行增加复选框；点击复选框只改变批量选择，不触发账号切换。
- 账号卡片标题区增加“批量删除”按钮；未选择账号时禁用，并显示已选择数量。
- 点击批量删除后显示二次确认，明确账号数量以及关联课程、签到项和任务会一并删除。
- 删除期间禁用重复提交。成功后清空批量选择并重新加载账号、课程、任务和运行记录。
- 若当前账号被删除，自动选择剩余列表中的可用账号；若账号全部删除，清空课程和签到项状态。
- 保留现有单账号删除、重新扫码、编辑备注和同步课程入口。

## 后端接口与数据流

- 新增账号批量删除请求模型，接收去重后的正整数账号 ID 列表，并限制最大数量。
- 新增 `POST /api/class-cube/accounts/batch-delete`。
- 服务层沿用当前用户作用域；普通用户只能删除自己的账号，管理员按现有规则操作。
- 仓储层在一个数据库事务内校验所有目标账号均存在且可访问，然后批量删除。数据库现有级联关系负责清理关联课程、签到项、任务和相关记录。
- 任一账号无权访问或不存在时，整批失败并回滚，不产生部分删除。
- 接口返回实际删除数量，前端据此显示成功消息。

## 错误处理

- 用户取消确认时不发出请求。
- 请求失败时保留当前选择，显示服务端错误，方便重试。
- 批量删除不会扩大现有账号可见范围，也不会在日志中输出登录凭证。

## 验证

- 前端验证账号行在当前截图宽度与窄屏断点下完整显示状态和操作按钮。
- 前端验证选择、取消、按钮禁用、确认取消、成功刷新和失败保留选择。
- 后端验证空列表、重复 ID、越权 ID、缺失 ID、成功批量删除和事务回滚。
- 前端构建通过，后端相关测试通过。
